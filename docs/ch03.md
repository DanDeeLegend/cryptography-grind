## 3.1 One Feistel round, traced

MiniDES is DES shrunk to a size you can follow: 16-bit block (two 8-bit halves), 4 rounds, 12-bit round keys, but the *same
round structure* and DES's real S-boxes S1 and S2. One round, with real values (`python -m cryptolab.ch03.mini_des`):

| Step | Value |
|---|---|
| L / R | `11010010` / `01111001` |
| round key K (12 bits) | `101001101100` |
| 1. expansion E(R): 8 → 12 bits (some bits reused) | `101111110010` |
| 2. key mixing: E(R) ⊕ K | `000110011110` |
| 3. S1 input `000110` → row 0, col 3 → output | `0001` |
| 3. S2 input `011110` → row 0, col 15 → output | `1010` |
| 4. permutation P(S1‖S2) = F(R, K) | `00001011` |
| 5. new R = L ⊕ F(R, K); new L = old R | `11011001` / `01111001` |

**Why a Feistel network?** `L', R' = R, L ⊕ F(R, K)` is invertible *whatever F is* (even if F is not), so DES can use a
lossy S-box function and still decrypt: run the same rounds with the round keys in reverse order. The S-box is the only
non-linear part; without it the whole cipher would be a linear function an attacker could solve. Real DES: 64-bit block,
32-bit halves, 48-bit round keys, eight S-boxes, 16 rounds.

## 3.2 Meet-in-the-middle on double encryption

Double encryption `C = E_k2(E_k1(P))` with two independent n-bit keys *looks* like 2n bits of security. It is not:
encrypt P under every k1 and store the results; decrypt C under every k2 and look each result up. A hit is a candidate
`(k1, k2)`.

On MiniDES (16-bit keys): brute force needs up to **2^32 ≈ 4.3 billion** double-encryptions; the attack did it in
**131,072 = 2·2^16 operations** (plus a 65,536-entry table) and found exactly one key pair out of four known
plaintext/ciphertext pairs (a 16-bit block makes one pair ambiguous, so extra pairs filter false candidates).

**Mapped to real DES.** 2DES has 2×56 = 112 key bits, but the same attack costs about 2^56 + 2^56 ≈ **2^57** cipher
operations, not 2^112, so 2DES is barely stronger than DES. (It needs ~2^56 table entries of memory, a practical obstacle but
not a security argument.) That is why the standard answer is **3DES**: with three keys the attack costs ~2^112, not 2^168
(for the 2-key variant, other attacks apply). Moral: security does not simply add up when you chain ciphers.

## 3.4 Brute-forcing a reduced-key cipher

Real DES (PyCryptodome) with all but *n* of the 56 effective key bits fixed, worst case (the last key tried):

| Unknown bits | Trials | Seconds | Keys/second |
|---:|---:|---:|---:|
| 12 | 4,096 | 0.04 | 91,610 |
| 16 | 65,536 | 0.72 | 90,786 |
| 20 | 1,048,576 | 13.43 | 78,089 |
| 22 | 4,194,304 | 53.68 | 78,128 |

Time doubles with every added bit (22 → 20 bits is 4× fewer keys and ~4× less time). At **~78,000 keys/s**, the average
for full 56-bit DES (2^55 trials) would be about **14,600 years on one Python process**. That number is a measurement of
*this* script on *this* machine, and the point is the scaling, not the speed: dedicated hardware tests billions of keys
per second per chip, and the 1998 EFF "Deep Crack" machine (custom ASICs) recovered a DES key in a few days. DES fell
because its key space is searchable, not because the algorithm is flawed.

## 3.5 3DES vs AES-128 benchmark

CBC mode, best of 5 runs, this sandbox (x86-64 with the AES-NI instruction):

PyCryptodome:

| Data size | 3DES MB/s | AES-128 software MB/s | AES-128 AES-NI MB/s | AES(sw)/3DES | AES-NI/3DES |
|---:|---:|---:|---:|---:|---:|
| 64 KiB | 8 | 253 | 805 | 32.1x | 102.0x |
| 1,024 KiB | 8 | 230 | 868 | 27.6x | 104.1x |
| 16,384 KiB | 8 | 236 | 695 | 30.5x | 89.8x |

OpenSSL (`cryptography` package):

| Data size | 3DES MB/s | AES-128 AES-NI MB/s | AES-NI/3DES |
|---:|---:|---:|---:|
| 64 KiB | 25 | 1,362 | 53.6x |
| 1,024 KiB | 25 | 1,232 | 49.6x |
| 16,384 KiB | 25 | 591 | 23.5x |

**Interpretation.** AES-128 is far faster than 3DES here, by roughly **24x to 104x** depending on library, data size and
whether AES-NI is used. The *structural* reasons hold everywhere: 3DES runs DES three times (48 rounds of bit-level
permutations and 6-to-4-bit S-box lookups) on **64-bit** blocks, so it does many rounds per byte; AES-128 runs 10
byte-oriented rounds on **128-bit** blocks that map well onto table lookups and SIMD, and AES-NI executes a whole AES round
in one CPU instruction. The exact multiple is *not* a constant: PyCryptodome's 3DES is slow (8 MB/s) and widens the gap, so
quote the library and CPU with any figure. 3DES's 64-bit block also has a security problem the benchmark cannot show:
birthday collisions after ~2^32 blocks (the 2016 Sweet32 attack), which is why 3DES is deprecated.
